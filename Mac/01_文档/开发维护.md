## 回复流程

```mermaid
flowchart LR
    A[微信会话与新文字] --> B[身份和历史核对]
    B --> C[每位好友的独立上下文]
    C --> D[DeepSeek 生成回复]
    D --> E[待发送草稿]
    E --> F[重新定位好友并核对界面]
    F --> G[后台发送及结果核验]
    G --> H[本机会话记录]
```

微信成为前台应用时，助手暂缓界面操作，忙碌模式继续保持开启。用户离开微信后，待处理内容重新进入核对流程。输入框中已有用户文字时暂缓处理；发送结果不确定时暂停该好友，避免重复发送。

## 第一屏范围与活动说明

`scanChats(valid:)` 只读取聊天列表顶部第一屏，不提供全量扫描参数。启动、常规检查及新会话出现时均不遍历后续屏幕。列表已经在顶部时不再调整滚动位置，需要时先对齐顶部，之后不恢复原来的较低位置；`openChat` 只在第一屏定位目标，不向下翻找。

所有好友模式用启动时的第一屏建立基线，现有未读不回复。未见过的会话首次进入第一屏时，仅处理最新一条可识别文字，避免按累计未读数量批量带入历史。重复显示名只在当前第一屏判断；不声称全列表名称唯一。指定好友可直接以当前已打开私聊的快照开始，不依赖启动时读取整份聊天列表；切换到其他聊天后，目标不在第一屏时暂缓定位。消息行无法与旧基线衔接时，重新建立基线并清空该好友用于生成回复的历史上下文，避免沿用旧内容。所有好友流程只保留一份待发送草稿；切到其他聊天后，如果草稿目标不在第一屏，则等待其返回，或在用户忽略草稿后继续，不扩大查找范围。

每种活动（含自定义）的说明按活动 ID 分别保存。`ActivityDescriptionsStore` 使用 `v6.activityDescriptions` 偏好字典，编辑后立即保存，`chooseActivity` 恢复该活动上次内容，`saveActivity()` 用于显式确认，`activitySaveStatus` 显示保存状态。迁移时保留旧 `v2.activityID` 对应的 `v2.activity` 当前说明；其他活动继续使用各自预设，首次使用的自定义活动保持自己的空白说明，不继承其他活动内容。保存时同步旧版当前活动键，保持配置兼容。

## 个人档案与回复设置

Markdown 导入只读取本地 `.md` 或 `.markdown` 文件，支持 UTF-8 和带 BOM 的 UTF-16，文件最多 256 KiB，正文最多 6,000 个字符。原文件不改写，正文中的图片、链接和引用文件不加载。导入与编辑属于待保存内容，回复使用用户已保存的版本。

档案保存在 `~/Library/Application Support/WeChatPracticeAssistant/Profile/profile.json`，目录权限为 700，文件权限为 600。档案启用开关默认关闭；只有开启且存在已保存正文时，生成微信回复的请求才附带整份简介。选定好友和所有好友使用同一份档案，应明确提醒用户只保存适合该回复范围的内容。

语气支持「自然简短」「温柔友好」「礼貌专业」「轻松幽默」「俏皮活泼」；互动方式支持「简洁应答」「自然接话」「趣味互动」；聊天拓展支持「不主动拓展」「顺势接一句」「适度追问」「持续延伸话题」。这些选项合并进生成指令，扩展回答最多两至三句短句、一个相关问题；持续模式要求每次正常回复以相关小问题延伸。结束信号优先收尾，严肃或紧急内容优先认真回应。持续模式只响应新文字，不增加定时主动消息。

忙碌模式启动时冻结本次的已保存档案、档案启用状态、时长、轮数模式和回复设置，运行期间不重新读取导入文件或套用编辑中的内容。档案作为人物背景资料处理，不作为执行指令；保留临时助手身份，不凭简介推断未知事实或替本人作出承诺。

## 持续延伸的生成与核验

仅「持续延伸话题」使用结构化生成，要求模型返回两个字符串字段：`reply` 和 `follow_up`。`shouldExtendTopic` 根据本次新文字中的收尾、停止或紧急信号决定是否需要追问；正常轮次要求 `follow_up` 非空、以问号结尾，两个字段合计恰好一个中英文问号。支持组合收尾文字及忙碌、稍后再聊等信号。出现收尾、停止或紧急信号时，`follow_up` 必须为空，组装后的回复也不能包含问号。

`validatedExtendedReply` 校验后组装为正文及后续问题，微信只收到普通文字，不接收 JSON。格式或追问不合格时，同一次生成流程最多要求模型纠正一次；仍不合格便抛出错误，不进入发送队列；状态标为「回复校验」，再按已有规则等待 15 秒重试。连续三次处理失败时只暂停这位好友，其他好友和忙碌模式继续。

此校验约束返回格式和问号数量，话题是否相关、问题是否自然仍依赖模型回答质量。每位好友的模型上下文仅保留最近 8 条历史消息；不限轮数不会扩大这部分上下文。发送前继续执行后台让行、好友身份与消息历史核对、输入草稿保护和结果核验。

## 时长与轮数规则

忙碌时长保持有限，范围为 5–480 分钟；有限回复轮数范围为每位好友 1–100 轮。`unlimitedReplies` 默认关闭，开启时跳过指定好友和所有好友流程中的轮数上限判断，实际发送计数仍保留。数字轮数偏好不因开启无上限而覆盖，关闭时恢复原值。

界面提供常用选项与原生选择控件，状态摘要必须区分「每位好友最多 N 轮」和「无上限」。无上限不绕过时长截止、停止语句、本人接管、前台让行、草稿保护和发送核验。

## 构建和测试

从项目根目录运行：

```sh
./05_构建工具/build.command --build-only
```

脚本在 Desktop/iCloud 之外的临时工作目录完成编译、本地测试和签名，再生成去除资源分叉与扩展属性的 ZIP，并在该临时目录解压一份进行严格签名核验。通过后，整个构建工作目录移入本项目的 `06_发布版本/构建产物`，包括应用、ZIP、生成图标和构建辅助文件；不会把构建结果散留在临时目录。

构建产物和更新前备份同时提供不含资源分叉及扩展属性的 ZIP。Desktop/iCloud 可能重新给项目内应用副本附加 Finder 元信息，因此安装来源使用已验证的 ZIP。日常仍打开原安装位置；项目内的应用副本用于查看和备份。

现有测试通过应用的 `--self-test` 入口执行，使用内存数据，不读取真实聊天、钥匙串或真实记录，也不请求 API。组织文件之后必须确认新路径能正确编译并运行这些测试。

安装使用：

```sh
./05_构建工具/build.command --install
```

安装前必须退出正在运行的助手。脚本检查目标应用身份，将旧版应用和 ZIP 保存在 `06_发布版本/更新前备份`，再从已验证的 ZIP 解压到一个新的临时目录，核验签名后更新原安装位置，并再次核验安装结果。临时安装目录随后清理；安装不会自动开启忙碌模式。

## 本机数据

会话记录位于 `~/Library/Application Support/WeChatPracticeAssistant/Sessions/`，个人档案位于同级 `Profile/profile.json`。偏好设置由 macOS 管理，API 密钥保存在钥匙串。源码仓库不包含这些用户数据、偏好快照或密钥。

当前维护源码在 `02_源码/`，测试在 `03_测试/`。构建脚本没有第三方包依赖，使用本机 Swift 编译器及 Cocoa、SwiftUI、ApplicationServices、Security 系统框架。
